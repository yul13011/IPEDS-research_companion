### Cross-cutting cause: resolver non-determinism (affects #4, #5, #7, and the intermittent face of #6)

The app's downstream routers (`discovery_question`, `catalogue_scope`, `aggregate_question`, the degrees route, the populations guard) are **deterministic given a fixed question string**. But the v2 resolver does **not** pass the user's words through — it makes a fresh Haiku call that (a) classifies an *operation* and (b) **rewrites** the question into a `standalone_question`. Both outputs vary run-to-run, and the rewrite's wording changes which deterministic branch fires. So the *same* user question is effectively a new coin-flip each time:

- **#4** — the rewrite drops the "what data do we have" discovery trigger → falls off the discovery route; then `catalogue_scope(sq)` flips → planner (990) vs measure planner.
- **#7** — the rewrite occasionally trips `catalogue_scope`/`aggregate_question` → population path → cross-release title guard (`populations.py:166`) fires.
- **#6** — the hedge appears only on runs whose narrator path echoes raw rows.

**Durable fix direction:** evaluate the key routers on the **original** question (not just the rewrite) in the v2 path, and/or give the resolver explicit, deterministic operations for discovery and single-institution trends so phrasing drift can't change the route.

**✅ Implemented 2026-11-08 (pending commit):** "route on the original words" is now in place for the two decisions that were flipping — a discovery pre-route in `resolver_v2.handle()`, and a `route_text` parameter threaded through `agent._answer`/`_ask` so the `discovery_question` and `catalogue_scope` gates read the user's original question while the model's rewrite is still used to execute. Fixes #4 and #7 (6/6 deterministic each, regression + 27 offline tests green). #5 (extract-builder seeding) and #6 (narrator hedge) are untouched and still open.

# IPEDS Research Companion response rules

Applied October 17, 2026, adapting the graduation prototype's main rules to the broader reviewed IPEDS catalog.

1. Answer first in plain language, normally 2–5 sentences. Generate statistical prose from the validated result, never from the planner's unverified numerical claims. Do not add a second model call for a summary.
2. Use line charts for trends, bar charts for institution or subgroup comparisons, and a direct answer/table for a single lookup. Explicit table and export requests take priority; a chart-plus-table request may show both. Hide the main table when a chart is displayed unless requested. Chatbot results expose only Display table, Definitions & sources, and Download Data as primary controls. Underlying counts/status are optional within the table view. Combine definitions and readable codebook references; keep internal plans, SQL and technical identifiers in downloads. Group Excel, CSV and technical audit JSON in one Download Data menu. Keep alternative extract layouts and selection editing in the builder, and omit per-answer model diagnostics. Retain full exports and visible substantive warnings.
3. Use source-based readable measure and institution labels. Apply automatic neutral titles, institution/population/period subtitles, accessible styling, value labels, adaptive height and sensible ordering under CHART_READABILITY.md. Preserve explicit user titles, labels, colors and presentation edits.
4. Percentages already use a 0–100 scale. Never multiply them again. Preserve counts and SAT score units. Distinguish `not_collected` from `missing`/not reported. Never substitute zero or assume a missing value was suppressed.
5. Explain reporting periods, outcome years, entering cohorts and nominal class-of years according to the measure. Graduation cohort conversion adds six; admissions class-of conversion subtracts four. Retain provisional, comparability and benchmark-discrepancy warnings.
6. Use previous scope only for referenced follow-ups. A new self-contained data question must not inherit institutions, years or subgroups. Show an Interpreted as note when reusing prior scope.
7. Resolve institutions against the data. Ambiguous names produce a clarification listing candidates; the user can supply an exact name/UNITID or use the extract builder. No guessed institution or published partial result.
8. Explain unsupported scope and point to supported comparisons, discovery or the extract builder. Outside reviewed measures, use the full-catalog typed query engine; a proposed plan is not numerical execution approval. Never equate an unimplemented query with absent source data. National/state/sector queries use explicit directory populations, validated source counts and audited coverage; known benchmark discrepancies remain blocked (POPULATION_AGGREGATES.md). Custom URM still needs a definition. Population rates pool matching numerators and denominators, never implicit averages of institutional or subgroup rates.
9. Display-only edits reuse the exact result/provenance without querying again. Supported conversational edits: show/hide table; line/bar chart; title; x/y labels; valid y range; a single overall color; bar sort order. Explain unsupported edits without pretending success. Per-series styling, fonts and legend placement are not implemented.

Implementation: `responses.py` holds deterministic summaries, display defaults, context gating and display-edit parsing; `agent.py` applies planning/clarification rules; `components.py` renders chart/table/source evidence; `ui.py` routes display edits before calling the planner. All example and builder results use the same summary layer.

Scope of validation: deterministic real-data tests and mocked model transport. These rules do not constitute a new live-model accuracy evaluation.

Definitions & sources and Download Data appear as adjacent buttons on one row.

October 19 step 3: familiar reviewed questions retain their validated numerical route. Other questions can use catalog tools to propose selections, coded filters, grouping, typed calculations and joins. Validate exact source IDs, code evidence, physical key columns and each source year. Save proposals separately, preserve unresolved semantics, and never display invented values. Clarification questions must identify the actual unresolved institution, population, time period or method. Catalog follow-ups remain separate from reviewed-result follow-ups.


## Catalog execution update (October 19, step 4)

Eligible catalog-discovered direct observations now execute and use the same Display table, Definitions & sources and Download Data controls as reviewed results. Use dynamic source labels/definitions, retain source reporting periods, and do not invent fixed measure IDs. Blocked plans remain explicitly unexecuted, without numerical tables/downloads. Retain official unknown/nonresident categories; no implicit aggregation or custom regrouping. See CATALOG_EXECUTION.md for execution boundaries and latency evidence. Latency belongs in audit/test metadata, with no additional chat dropdowns.


For an unqualified category breakdown, return source counts. Do not invent percentages as an execution requirement. If shares are explicitly requested, produce one supported category numerator per output with the same-population denominator. Explain first-year/first-time population interpretation and institution-versus-college reporting; retain source gender-category limitations without inferring unknown/another-gender counts or zeros.

General calculation update: unfamiliar category percentages, compatible category ratios, disjoint sums and category differences use source-grounded field meanings and relationship checks rather than an approved field-name list. Apply exact source population/row selectors, compatible units/periods and result checks. A test-case file is not an execution prerequisite. Return semantic feedback to the planner for bounded source inspection and repair before asking the user to rephrase. Never ask the user to choose database columns or approve a routine formula; ask only for a genuinely unresolved intent or methodological choice. Unknown evidence is a validation limitation, not proof that the data is absent. See GENERAL_CALCULATIONS.md for implemented scope, remaining limits and evaluation evidence.

Version-2 query-engine update: grouped extracts, explicit-domain aggregates, validated fact joins, weighted means and typed multi-step formulas may execute after metadata and observed-grain checks. Treat category codes as labels, preserve requested periods and cohort years, and validate growth input order. Missing selected institutions propagate in combined calculations unless complete cases were explicitly requested. Existing primary result controls remain unchanged. See QUERY_ENGINE.md for exact bounds and evidence. Earlier proposal-only/same-row-only statements above are historical, superseded for these supported operations.

Conversation memory update: use the bounded recent conversation and active analytical scope across reviewed/catalog routes. Resolve ordinary continuations and earlier references before routing; current explicit changes override prior scope. Clarify ambiguous references, never silently choose between equally plausible analyses. Historical answers are context, not fresh evidence. Revalidate every analytical change; display-only edits reuse their result. New conversation clears session context. See CONVERSATION_MEMORY.md.

Institution confirmation rule supersedes older alias/substring shortcuts in chat: resolve original user wording before memory/model expansion. Exact official names or UNITIDs and the documented safe abbreviations can proceed. All other non-exact names require explicit selection even if one plausible candidate exists. Never auto-select the highest-ranked candidate or a flagship campus. Show location/UNITID and allow refinement or cancellation. Preserve confirmed UNITIDs for follow-ups; unavailable years must not select a replacement campus. See INSTITUTION_CONFIRMATION.md.


Chart readability update: horizontal comparison bars, direct formatted values, wrapped horizontal labels and adaptive height; line trends use at most four series per panel with shared scales for comparable units. All requested series remain present. Totals are separated from categories; Unknown/Nonresident remain visible. Default percent comparison axes are 0–100, focused percentage trends and user ranges are disclosed. Cohort/reporting labels come from actual source timing. See CHART_READABILITY.md.

Result text separation: highlight only substantive caveats; planner assumptions and generic validation explanations belong in technical_notes/downloads. Keep unrecognized engine warnings visible. Definitions & sources presents concise source-based definitions, selected population/reporting period, a plain-language calculation and release/codebook references. Full definitions, variable codes, SQL, sheet/row references and proofs remain in Excel/JSON. Preserve college/reporting-scope, missingness, comparability, source-conflict and provisional caveats. See RESULT_TEXT_RULES.md.

Working status: show real request-stage notifications inside the assistant conversation bubble. Institution identification/matching, conversation resolution, catalog inspection, model planning rounds, plan validation, annual data reads, joins/calculations and answer preparation report their own start. Keep the current stage while it is running; do not invent percentages, completion estimates or model-internal activity. Use one replaceable muted line, with the existing spinner; clear it on completion or failure. Stage notifications are request-scoped and do not enter the final answer or source data.

Chart edits: ordinary axis-title requests such as `Change x-axis to "Year"` are label edits without requiring the literal word `label`. Preserve quoted text without its outer quotation marks. Distinguish unquoted numeric ranges from labels. Supported display edits use the latest available numerical result even if the immediately preceding response was a clarification/rejected edit. Verify changes against rendered charts and visible tables, preserving underlying data and avoiding new analytical/model calls. See CHART_READABILITY.md for verified command examples and remaining limits.

Trend follow-ups change analytical time scope: resolve an inclusive duration before treating an isolated four-digit date as the entire selection. “10-year trend ending with Fall 2024” means all observations from Fall 2015 through Fall 2024. Preserve the institution/measure/population, request and validate the annual data, then choose a line chart. Pure time-only continuations are not institution names. See TIME_SCOPE.md for default intervals, explicit-date protection and verified replay evidence.

Request → plan → result checks now precede fact queries and publication. Preserve explicit institutions/periods, independent requested observation counts, supported source-backed breakdowns/percentage outputs and known enrollment populations. Validate actual returned periods per institution; do not quietly render a shorter trend. Missing observations keep their slots and receive a caveat when too few reported values remain. Invalid cached results cannot expose summaries/charts/tables/downloads. Formatting turns are not the active analytical topic. These bounded checks supplement existing source validators; see INTENT_VALIDATION.md for coverage, evidence and limits.

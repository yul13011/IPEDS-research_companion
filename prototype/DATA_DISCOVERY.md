# Questions about available data

Requests such as “What data do we have on faculty?” use a source-backed metadata overview rather than a statistical plan or a list of reviewed starter measures.

- Strip conversational filler and search table definitions separately from physically present variable definitions. Existing catalog synonyms aid retrieval.
- Generic college/university words are context when a more specific topic is present ("college tuition" searches "tuition"); a generic-only request retains its words.
- Build annual concepts before ranking or applying the eight-feature limit. Require the exact survey, a stable source description and population, at least two shared columns and 60% overlap relative to the smaller schema; do not combine distinct tables within the same release. Completion-time percentages, institution types and changed definitions remain distinct. Table-name year substitution is no longer the grouping mechanism. This is a navigation grouping, not a numerical comparability certification.
- Move annual dates and entering cohorts out of feature headings. Retain population labels in headings, summarize cohorts by documented institution type, and label graduation outcome dates separately. Keep every original title, reporting period, release/table and record reference in annual coverage evidence. Source title dates can disagree with coverage labels; do not rewrite either to force agreement.
- Show up to eight matched concepts: source-backed description, survey, documented periods/cohorts and up to four physically verified field examples retrieved separately within each concept. If examples cannot be verified, state that explicitly. Keep technical table identifiers in Definitions & sources rather than the narrative. Do not invent populations, breakdowns or values.
- Keep source records in **Definitions & sources**. Availability describes the supplied catalog, not complete reporting by every institution or approved arithmetic for every field.
- Group features by the exact source survey name. Show the most common reporting-period coverage once per survey and mark each feature whose coverage differs. Compress contiguous runs only when every intervening annual period is present with identical source formatting; retain gaps and mixed period labels explicitly. Normalize punctuation in narrative text, preserving the exact originals in evidence.
- Validate that the overview has no repeated annual source records, retains all source periods, reproduces source-derived cohort coverage, removes singular cohort labels from headings, and has evidence for its example fields before display. Where similar concepts must remain separate because the evidence differs, explain that separation.
- Explicit years filter release years; label this and show actual reporting periods separately. Empty searches do not establish absence. A request with no topic asks for one.
- Explicit discovery bypasses institutional clarification, statistical planning and conversation rewriting. In AI mode, step 1 now proposes possible concepts/search phrases and step 5 writes from verified source evidence. Catalog lookup, grouping, coverage and physical-availability checks run in code with no annual fact query. Offline mode retains the original-keyword search and verified template. Ordinary analytical requests retain existing institution and query validation.

## AI-assisted interpretation and search expansion

`discovery_interpretation.py` makes one bounded proposal call using the existing selected model. The original question and original keyword search remain authoritative. The prompt targets at most three interpretations, with a hard cap of four, 1–3 phrases per interpretation and a 1,400-token response budget. Models cannot add dates, SQL, source values or an institution selection. Failed proposals, missing credentials and API errors preserve the original search.

Each concept must match a source table or variable definition that physically exists in the requested releases. Concept tokens are required together; proposed phrase tokens must co-occur with them in the same record. Common singular/plural variants are allowed within each required token (salary/salaries), not as an alternative to the whole concept. Table and field results get separate bounded allocations so annual copies of variables cannot crowd out table descriptions. A failed phrase is not used; a concept without evidence is rejected without making an absence claim.

Original and verified expansion hits are combined and deduplicated; every original hit remains in the search audit. Display ranking prioritizes verified interpretations, also admitting original-keyword matches directly in source titles. Original body-only incidental matches do not automatically fill the eight-concept display when verified interpretations exist. With no verified expansion, original ranking and topics remain unchanged. The audit records the proposals, accepted/rejected concepts, phrase-level source references, original and merged record IDs and ranking policy.

Interpretations are tentative. Physical catalog matches establish documented availability, not semantic equivalence between an everyday phrase and an IPEDS category. Ambiguous alternatives remain distinct, with a required qualification in the narrative; uncertainty notes and source references remain inspectable. Only source-verified concepts represented by selected evidence pass into the writing package. No clarification is forced merely to explore alternatives; analytical population/institution/calculation rules remain unchanged.

Interpretation and writing usage are aggregated with separate stage timings and costs. Unknown usage remains unknown. Typically two calls occur in AI discovery (one interpretation, one writing); missing topics or no matching data can skip writing. No automatic retries are added. New real-source/transport/UI tests cover made-up concepts, same-record matching, physical availability, year scope, original-hit retention, fallback, ambiguity, singular/plural retrieval and combined usage.

## AI writing at step 5

`discovery_narrative.py` packages the question, selected concepts, exact annual titles/periods/cohorts, full table descriptions and selected variable definitions, source issues and mandatory qualifications. Source text is split into selectable passages with stable quote IDs; it is not silently truncated. Local file paths and statistical values are not part of this package. Its serialized size is capped at 220,000 characters, with a verified-template fallback if exceeded.

The model can rewrite prose, not retrieve more data, change rankings, drop selected concepts, create a plan or query facts. It returns structured survey blocks, short points, topic references and passage references. Distinct concepts remain separate; identical descriptions may share a point. The app renders exact survey headings. It shows reporting periods directly only when coverage agrees across those topics and remains concise; otherwise it directs users to the detailed per-area coverage.

Before publication, code checks schema, source-passage/topic references, complete nonduplicated topic coverage, permitted surveys, numeric support, reading budgets, technical identifiers, universal/equivalence claims and selected material scope errors (including nonmedical staff and 150%/200% completion mislabeled as on-time). Required qualifications are appended by code, including provisional status, source-release year filters and cohort/loan-label distinctions where relevant. Exact coverage and the original template remain under **Definitions & sources → Detailed catalog coverage**. The writing package, source references, check results, model usage and timings are inspectable under **Answer construction and source checks**.

Editorial targets have a bounded 10% total-word margin so a small overrun does not discard verified prose. Verified annual date suffixes in point titles may be moved to the existing detailed coverage before validation; the raw draft and changes are retained in the audit. Only one-year spans whose years are present in those topics' documented reporting periods qualify. Unknown dates, dates in explanatory prose and unsupported references remain subject to rejection. This is deterministic formatting, not another model call or a relaxation of source support.

One attempt per model stage is allowed (45-second provider timeout per stage, no SDK retries). Unavailable interpretation falls back to original search; unavailable/invalid writing retains the verified source answer with a muted explanation. Returned token usage is counted even if a draft is rejected. When usage is not returned, cost is unknown rather than reported as zero. Estimated rates are based on [Anthropic's pricing documentation](https://platform.claude.com/docs/en/about-claude/pricing), checked October 20, 2026.

Reference validity and lexical guards do not prove semantic entailment. Automated model reviews are diagnostic and can overflag valid paraphrases; exact definitions remain authoritative. Tests combine source/qualification corruption cases, route/UI/fallback checks and live paired evaluations of readability, source accuracy, qualification retention, latency and cost. Evaluation-only reviewer calls do not run in production and their costs/times are recorded separately.

Limitations: bounded keyword/synonym retrieval can miss unfamiliar terminology, include related areas or omit areas beyond the eight-family display cap. This is not an exhaustive semantic inventory. Institution-specific completeness needs an analytical query. Fields without table-level documentation or at a documented location that is physically absent are not advertised by this overview. No new calculation capability is implied.

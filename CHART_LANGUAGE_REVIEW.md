# Chart editing through language: local review and repair

This report records the earlier local-parser repair. Conversational AI mode has since been replaced with [Claude-first intent routing](INTENT_ROUTING.md); the rule-based parser is now the explicit offline path only.

October 23, 2026. Tested the redesigned application against real local IPEDS data. No live model calls, deployment changes, or database changes.

## Finding

The instability reproduced locally. Chart-edit interpretation uses deterministic regular-expression rules rather than the general language model. Equivalent wording often missed those rules, and some display requests returned no local match, allowing the UI to send them to the analytical/model route. This is primarily an interpretation/routing problem, not evidence of insufficient hosting capacity.

A deliberately varied 46-case matrix covered 36 supported formatting requests, six unsupported/invalid requests that must clarify, and four new-data requests that must remain on the analytical route. This is a targeted regression set, not a statistical estimate of accuracy across arbitrary natural language.

| Expected behavior | Before | After |
| --- | ---: | ---: |
| Apply supported chart edit | 14/36 | 36/36 |
| Reject unsupported/invalid edit safely | 3/6 | 6/6 |
| Preserve routing for a new data question | 4/4 | 4/4 |
| Total | 21/46 | 46/46 |

Evidence: `evaluations/chart_language_baseline.json` and `evaluations/chart_language_repaired.json`, generated by `prototype/tests/test_chart_language.py --evaluate baseline` and `--evaluate repaired` respectively.

## Bugs found and changes

- Requests prefixed with "Can you", "Could you", or "Please" often failed. Normalize request politeness before chart-edit matching while preserving literal text.
- Optional articles and prepositions broke common requests: "hide the legend", "show the point markers", and "move the legend to the bottom". Accept those equivalent forms.
- The font alternative matched the start of "font size" and treated "size to 18" as a font name. Match the longer setting names first.
- The splitter protected double-quoted commas but split conjunctions inside quoted text, and did not protect single-quoted titles/footnotes. Use one quote-aware scanner for comma, semicolon, and command conjunction separators. Preserve apostrophes within words and quoted wording such as "Enrollment and show table" as literal text.
- Compound edits did not split before "move" or "rename". Recognize those command conjunctions while retaining the existing all-or-nothing behavior.
- Accept unambiguous series-color wording such as "Make Smith's line red" and "Change the color of Smith to red". Ambiguous "College" remains rejected.
- Recognize tested unsupported formatting phrases as clarifications instead of allowing an analytical fall-through. No support for dashed lines or label rotation was invented.
- Resolve rendered series names only for potential series-color commands, rather than building charts for every unrelated edit.

Implementation changes are confined to `prototype/chart_format.py` and `prototype/responses.py`; tests were added and registered. Source result rows and provenance remain unchanged by accepted edits.

## Validation

51 distinct selected unittest methods passed across three runs:

- 16 chart-language, chart-edit, formatting, density, and full chart-workflow tests: passed in 144.4 seconds. This run included the 46-case matrix, UI sequences, actual chart specs, PNG/SVG exports, color-picker/prompt interaction, undo/reset, and source-value preservation.
- 34 related purpose-routing, trend-follow-up, and categorical-observation tests: passed in 60.9 seconds.
- One added parser-to-export integration test: passed in 6.0 seconds. Verified natural-language font size, hidden legend, latest-value labels, and a single-quoted title reach the exported SVG with source information and unchanged results.

The extra integration test was adjusted during development to request value labels explicitly and inspect the layer containing the plot; initial assertions had assumed labels were on by default and the specification was unlayered. No application changes were needed for those assertion corrections.

UI tests patch the analytical/model entry point to raise if a tested display edit reaches it. The new sequence verifies polite commands, chart-type changes, quoted titles, compound color/axis edits, safe rejection, and continued use of the original result. Existing workflows verify that valid edits still work after a rejected edit and that format-panel settings survive prompt changes.

Actual salary-chart exports under `evaluations/chart_workflow/` were generated by the existing full-workflow tests. Visually inspected the 800×600 hidden-legend and prompt-edited PNGs; chart labels, values, edited colors/title, and source notes rendered. No full registered-suite claim is made.

## Remaining limits

### Owner-reported horizontal-axis follow-up

The owner subsequently reported the actual sequence: "Compare Ivy League admission rates in fall 2024." followed by "Set x-axis range to 0–10". This exposed a gap in the initial test matrix. The chart is a horizontal bar chart with percentages on X, but the command parser previously accepted numeric range changes only using Y-axis wording. The existing renderer already supports those value limits horizontally.

Added X-axis range/reset commands for horizontal bar charts, while retaining existing Y-axis numeric-range compatibility. X-axis range/reset requests on line charts clarify that the axis represents reporting periods; no years are filtered or relabeled as a numeric range. Percentage limits still reject out-of-bounds ranges. Also corrected percentage tick generation for custom ranges: a 0–10 range now uses generated numeric ticks rather than the full-scale fixed list, which would have left only a tick at zero.

The new `test_horizontal_admission_rate_x_range_and_reset_in_ui` exercises the exact owner sequence through Streamlit AppTest, checks the rendered X domain, reset to 0–100, rejection of 0–200, unchanged source results, no analytical/model call, and protection of the time-series X-axis.

Follow-up validation: all eight methods in `test_chart_language` and `test_chart_edits` passed in 54.9 seconds, including the exact owner-reported sequence and the earlier language matrix.

The owner then supplied a distinct wording, "reset x-axis range to 0-10". The bounded-range branch now accepts reset with explicit bounds as well as set/change/make; reset without bounds still restores automatic limits. The exact UI regression now exercises both forms, resets, invalid percentage bounds, and time-series protection. This expanded method passed in 40.6 seconds. The running local app was found on port 8516 with `--server.fileWatcherType none`, so source edits alone were insufficient to reload it; a normal app restart was initiated to activate the fixes.

This remains a bounded chart-edit grammar, not unrestricted conversational chart design. Tested examples work; arbitrary synonyms and complex multi-chart references are not certified. Dashed-line editing and label rotation remain unavailable and should clarify. Data changes such as adding an institution or changing observation years remain analytical requests. Ambiguous series names should be clarified rather than guessed.

Tests used Streamlit AppTest and the real renderer, with no live Claude calls. The existing running app may need a normal restart/refresh to pick up the updated modules; it was not restarted during this task. A future hosted-browser acceptance pass should repeat the owner's actual troublesome prompts before launch.

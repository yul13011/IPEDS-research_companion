# Definition-question support — October 22, 2026

## Problem and change

Owner selected “Test and fix definition questions” (F003). Baseline production entry-point probes in offline mode reproduced the routing problem: “Define graduation rate” could interpret **Define** as an institution, while instructional staff/UNITID/full-time enrollment definitions returned generic catalog-planning limitations. Baseline outputs are retained in `definition_questions_baseline.json`; these were offline reproductions, not baseline live-model latency measurements.

Added `prototype/definitions.py` and entry-point routing before institutional confirmation and analysis planning. Answers read supplied variable/table documentation; no institution selection or statistical query is needed. Exact variable/table identifiers, explicit release years, term comparisons and unambiguous definition follow-ups are supported. Numeric school queries and mixed requests are not consumed as simple definitions. Complete definitions and citations remain under the existing Definitions & sources popover.

AI selection is extractive: every displayed passage must occur verbatim (whitespace-normalized) in metadata actually supplied to the model. Glossary entries retain their complete qualifications; field definitions retain their opening population scope. Invalid output falls back to a direct source match; unavailable usage/cost remains unknown. Reviewed measure definitions such as admission rate use the existing mapping and formula, clearly labelled as app definitions, with supporting source fields and no model call. This does not harmonize all IPEDS measures or introduce new analytical defaults.

## Development findings retained

Initial automatic routing/exact-text checks passed eight cases, but manual reading caught three semantic/relevance issues: incidental salary clauses in an instructional-staff answer; generic graduation rate matched the registry ID `graduation_rate` and inherited a six-year scope; faculty excerpts could drop the distinction between designation and occupation. Tightened glossary matching, complete-entry preservation and registry-label versus explicit-ID matching. Subsequent review caught a missing admission-rate passage alongside a valid reviewed formula, and an extracted graduation fragment missing first-time/full-time eligibility. The reviewed route now deterministically presents its supporting definitions, and variable passages retain the opening scope. A final test initially required “first-time, full-time” in one order despite equally correct source wording “full-time, first-time”; corrected that test-only assumption. All final focused tests passed.

Initial/refined evidence remains separate: `definition_questions_live.json/log`, `definition_questions_live_refined.json/log`, `definition_questions_graduation_recheck.json/log`, `definition_questions_reviewed_rate_recheck.json/log`, and offline diagnostic artifacts. Do not treat initial automatic checks as manual acceptance. `test_definition_questions_live.py --live` incurs configured provider charges; the independent verifier does not.

## Limits

Bounded lexical/morphological retrieval can miss synonyms or distant paraphrases. Exact quotations establish source fidelity, not that every requested concept or every qualification has been correctly identified. Explicit glossary and population guards address observed failure classes, not arbitrary semantics. Definition lookups currently explain one source release at a time, asking a scope question for multiple releases. Multi-action requests stay on the existing planner route rather than silently losing the statistical request. Full combined suite and browser visual acceptance were not rerun; Streamlit interaction/rendering checks passed. Original data, institution statistics and the paused national benchmark reconciliation are unchanged.
